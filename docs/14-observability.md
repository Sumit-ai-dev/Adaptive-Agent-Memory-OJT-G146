## Logs

All backend events, agent state transitions, tool invocations, and database interactions emit structured JSON logs via `Loguru`.

### Standard Log Schema
Every log entry contains structured contextual metadata for correlation:

```json
{
  "timestamp": "2026-09-23T15:25:00.124Z",
  "level": "INFO",
  "service": "adaptive-agent-backend",
  "correlation_id": "corr_8f12a3b4c5d6",
  "user_id": "usr_99a8b7c6d5e4",
  "run_id": "run_12345abcde",
  "node": "retrieve_node",
  "message": "Retrieved 3 active experiences for task domain 'research'",
  "extra": {
    "domain": "research",
    "retrieved_ids": [
      "e458df8a-0209-4bf9-8581-c304d989cb21",
      "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d"
    ],
    "top_similarity": 0.842,
    "top_trust": 0.880
  }
}
```

### Logging Rules & Guardrails
- **Correlation ID Propagation:** Generated at the API gateway (`X-Correlation-ID`) and passed down through every LangGraph node execution.
- **Secret Redaction:** User BYOK API keys, Supabase service keys, and raw bearer tokens are strictly scrubbed before writing to logs.
- **Persistent Audit Tables:** While application stdout captures runtime operations, high-value state changes (task results, memory creation, trust score updates) are written directly to PostgreSQL `task_executions` and `trust_history` tables.

## Metrics

Operational and research metrics are tracked continuously to monitor agent performance, cost, and memory reliability.

### 1. Operational & System Metrics
| Metric | Type | Target / Threshold | Description |
|---|---|---|---|
| `api.request_latency_ms` | Histogram | $p95 < 250\text{ ms}$ (non-LLM) | Gateway endpoint latency |
| `retrieval.latency_ms` | Histogram | $p95 < 25\text{ ms}$ | Time spent querying pgvector HNSW index |
| `agent.execution_time_ms`| Histogram | $p95 < 5000\text{ ms}$ | Full 5-node agent execution time |
| `agent.turn_count` | Histogram | Mean $< 2.5$ turns | Number of tool/execution cycles per task |
| `error_rate` | Counter | $< 1.0\%$ | 5xx server or tool execution errors |

### 2. GenAI & Memory Telemetry Metrics
| Metric | Type | Description |
|---|---|---|
| `llm.tokens.prompt` | Counter | Cumulative input tokens dispatched via LiteLLM |
| `llm.tokens.completion` | Counter | Cumulative output tokens generated by models |
| `llm.cost_usd` | Counter | Estimated cost tracking across model providers |
| `memory.retrieval_rate` | Gauge | Percentage of tasks where active memories matched threshold ($\ge 0.70$) |
| `memory.quarantine_rate` | Counter | Number of memories transitioning to `deprecated` per day ($S < 0.35$) |
| `memory.trust_drift` | Histogram | Distribution of trust score changes ($\Delta S = S_{t+1} - S_t$) |
| `agent.reward_score` | Gauge | Moving average of deterministic task rewards ($R_t \in [0.0, 1.0]$) |

## Tracing

Full distributed tracing of the cyclical 5-node agent execution is handled natively through **LangSmith** and OpenTelemetry conventions.

```text
POST /api/v1/tasks/run
 └── LangGraph: AgentWorkflowRun [Trace Root: run_id]
      ├── Node: retrieve_node
      │    ├── Span: generate_embedding (all-MiniLM-L6-v2) [12ms]
      │    └── Span: pgvector_rpc (match_experiences) [8ms]
      ├── Node: execute_node
      │    ├── Span: prompt_assembly (augment with Strategy & Pitfall) [2ms]
      │    ├── Span: litellm_call (groq/llama-3.3-70b-versatile) [850ms]
      │    └── Span: tool_invocation (duckduckgo_search) [340ms]
      ├── Node: evaluate_node
      │    └── Span: deterministic_heuristic_check [1ms]
      ├── Node: reflect_node
      │    └── Span: litellm_call (extract_reflection_schema) [420ms]
      └── Node: trust_node
           ├── Span: ema_trust_calculation [1ms]
           └── Span: postgres_audit_write (trust_history + experiences) [15ms]
```

## Alerts

Automated alerts notify administrators and developers of operational degradation or abnormal agent behaviors:

| Alert Name | Condition | Severity | Action |
|---|---|---|---|
| **High API Error Rate** | Error rate $> 5\%$ over 5-minute window | Critical | Investigate backend exception logs and provider gateway status |
| **LLM Provider Outage** | 3 consecutive LiteLLM timeouts or 429 rate limit errors | High | Trigger automated failover from Groq to secondary provider or local Ollama |
| **Trust Quarantine Spike** | $> 10$ memories quarantined in 1 hour | High | Investigate potential negative transfer cascade or faulty evaluation heuristic |
| **High Inference Latency** | Agent run execution $> 15\text{ seconds}$ | Medium | Inspect external tool response times and LLM provider token generation speeds |
| **Database Connection Exhaustion** | Pool utilization $> 85\%$ | High | Check connection recycling and asyncpg session release in FastAPI middleware |
